## 5. อธิบายโค้ดทีละส่วน

### 5.1 นำเข้าเครื่องมือ

```python
import tkinter as tk
```

- `import` (อิม-พอร์ต = นำเข้า) คือดึงเครื่องมือที่มีคนเขียนไว้แล้วมาใช้
- `tkinter` (ทีเค-อิน-เตอร์) มาจาก **T**ool**k**it **inter**face = ชุดเครื่องมือสร้างหน้าจอ
- `as tk` (แอส = ในชื่อว่า) ตั้งชื่อเล่นให้สั้น ต่อไปพิมพ์ `tk.Label` แทน `tkinter.Label`

### 5.2 ข้อมูลตั้งต้น

```python
MONEY_TYPES = [1000, 500, 100, 50, 20, 10, 5, 2, 1]
```

- เป็น **list** (ลิสต์ = รายการ) เก็บชนิดเงินไทยทั้งหมด อยู่ใน `[ ]` คั่นด้วย `,`
- ชื่อเป็นตัวพิมพ์ใหญ่ทั้งหมด เพราะเป็น **constant** (คอน-สแตนต์ = ค่าคงที่) ซึ่งเป็นค่าที่ไม่เปลี่ยนตอนโปรแกรมทำงาน
- **ต้องเรียงจากมากไปน้อย** เหตุผลอยู่ในหัวข้อ 6

### 5.3 ฟังก์ชัน `calculate_change` (หัวใจของโปรแกรม)

```python
def calculate_change(change):
    result = []
    for money in MONEY_TYPES:
        count = change // money
        change = change % money
        if count > 0:
            result.append((money, count))
    return result
```

- `def` มาจาก **def**ine (ดี-ไฟน์ = นิยาม) ใช้ประกาศสร้าง **function** (ฟังก์-ชัน = ชุดคำสั่งที่ตั้งชื่อไว้ เรียกใช้ซ้ำได้)
- `change` ในวงเล็บเป็น **parameter** (พา-รา-มิ-เตอร์ = ค่าที่ส่งเข้ามาในฟังก์ชัน) คือยอดเงินที่ต้องทอน
- `result = []` สร้าง list ว่างไว้ใส่คำตอบ
- `for money in MONEY_TYPES:` แปลตรงตัวว่า "**สำหรับ** (for ฟอร์) เงินแต่ละชนิด **ใน** (in อิน) รายการ" คือ **loop** (ลูป = วนซ้ำ) ไล่ทีละตัว 1000, 500, 100, ...
- `change // money` ใช้ `//` ซึ่งเป็น **การหารแบบเอาแต่จำนวนเต็ม** เช่น `1873 // 1000 = 1` หมายความว่าใช้แบงก์พันได้ 1 ใบ
- `change % money` ใช้ `%` (เรียกว่า modulo โม-ดู-โล) ซึ่งเป็น **การหารแล้วเอาเศษ** เช่น `1873 % 1000 = 873` หมายความว่ายังเหลือ 873 บาทที่ต้องทอนต่อ
- `if count > 0:` ถ้าใช้เงินชนิดนี้อย่างน้อย 1 ใบ ค่อยใส่ในคำตอบ (ไม่งั้นจะได้ "แบงก์ 500 x 0" ซึ่งรก)
- `result.append((money, count))` โดย `append` (อะ-เพนด์ = ต่อท้าย) เพิ่มของเข้าท้าย list
  - `(money, count)` ในวงเล็บกลมเรียกว่า **tuple** (ทู-เพิล = กลุ่มข้อมูลที่จับคู่กันไว้) เช่น `(100, 3)` แปลว่า "แบงก์ร้อย 3 ใบ"
- `return result` (รี-เทิร์น = ส่งคืน) ส่งคำตอบออกไปให้คนที่เรียกใช้

> 🧮 **ลองคิดตามด้วยมือ: ทอน 1873 บาท**
>
> | ชนิดเงิน | `change // money` | `change % money` (เหลือ) |
> |---|---|---|
> | 1000 | 1 ใบ | 873 |
> | 500 | 1 ใบ | 373 |
> | 100 | 3 ใบ | 73 |
> | 50 | 1 ใบ | 23 |
> | 20 | 1 ใบ | 3 |
> | 10 | 0 (ไม่ใส่) | 3 |
> | 5 | 0 (ไม่ใส่) | 3 |
> | 2 | 1 ใบ | 1 |
> | 1 | 1 ใบ | 0 |

### 5.4 ฟังก์ชัน `money_name`

```python
def money_name(money):
    if money >= 20:
        return f"แบงก์ {money} บาท"
    else:
        return f"เหรียญ {money} บาท"
```

- เงินไทยตั้งแต่ 20 บาทขึ้นไปเป็นธนบัตร ต่ำกว่านั้นเป็นเหรียญ
- `if` (อิฟ = ถ้า) / `else` (เอลส์ = นอกนั้น)
- `f"..."` เรียกว่า **f-string** (เอฟ-สตริง โดย f มาจาก **f**ormat ฟอร์-แมต = จัดรูปแบบ) ใส่ตัวแปรใน `{ }` ได้เลย เช่น `f"แบงก์ {100} บาท"` จะกลายเป็น `"แบงก์ 100 บาท"`

### 5.5 ฟังก์ชัน `on_calculate` (เมื่อกดปุ่ม)

```python
def on_calculate(event=None):
    price_text = price_entry.get().strip()
    paid_text = paid_entry.get().strip()
```

- ชื่อ `on_...` (ออน = เมื่อ) เป็นธรรมเนียมตั้งชื่อฟังก์ชันที่ทำงาน "เมื่อเกิดเหตุการณ์" อ่านว่า "เมื่อคำนวณ"
- `event=None` (อี-เวนต์ = เหตุการณ์, นัน = ไม่มีอะไร) เพราะเวลากด Enter ตัว tkinter จะส่งข้อมูลเหตุการณ์มาให้ แต่ตอนกดปุ่มไม่ได้ส่งมา จึงตั้งค่าเริ่มต้นเป็น None เพื่อให้รองรับทั้งสองแบบ
- `.get()` (เก็ต = เอามา) ดึงข้อความในช่องกรอก
- `.strip()` (สทริป = ลอกออก) ตัดช่องว่างหัวท้าย เผื่อผู้ใช้เผลอเคาะ spacebar

```python
    if not price_text.isdigit() or not paid_text.isdigit():
        show_message("กรุณากรอกเป็นตัวเลขจำนวนเต็มเท่านั้น", "red")
        return
```

- `.isdigit()` (อิส-ดิจิท = เป็นตัวเลขไหม) ตอบ True ถ้าทุกตัวเป็นเลข 0–9
- `not` (น็อต = ไม่) กลับค่าความจริง, `or` (ออร์ = หรือ) ถ้าข้อใดข้อหนึ่งจริงก็ถือว่าจริง
- `return` เปล่าๆ แปลว่า "จบฟังก์ชันตรงนี้เลย" ไม่ต้องคำนวณต่อ
- เรียกการตรวจแบบนี้ว่า **input validation** (อิน-พุต แว-ลิ-เด-ชัน = ตรวจสอบข้อมูลที่ผู้ใช้กรอก) เพราะถ้าไม่ตรวจ ผู้ใช้พิมพ์ "abc" แล้ว `int("abc")` จะทำให้โปรแกรมพัง

```python
    price = int(price_text)
    paid = int(paid_text)
```

- `int(...)` แปลงข้อความ `"100"` เป็นตัวเลข `100` ต้องแปลงก่อนเพราะข้อความเอามาลบกันไม่ได้

```python
    if paid < price:
        show_message(f"เงินไม่พอ ขาดอีก {price - paid} บาท", "red")
        return

    change = paid - price
    if change == 0:
        show_message("จ่ายพอดี ไม่ต้องทอนเงิน ✔", "green")
        return
```

- ตรวจกรณีพิเศษก่อน: เงินไม่พอ หรือจ่ายพอดี

```python
    text = f"ต้องทอนทั้งหมด {change} บาท\n\n"
    for money, count in calculate_change(change):
        text = text + f"{money_name(money)}   x {count}\n"
    show_message(text, "black")
```

- `\n` คือ **ขึ้นบรรทัดใหม่** (n มาจาก **n**ew line นิว ไลน์)
- `for money, count in ...` ใช้ **แกะ tuple** ทีละคู่ เช่น `(100, 3)` จะได้ `money = 100`, `count = 3`
- `text = text + ...` ต่อข้อความไปเรื่อยๆ ทีละบรรทัด

### 5.6 `show_message` และ `on_clear`

- `result_label.config(text=..., fg=...)` โดย `config` มาจาก **config**ure (คอน-ฟิก-เกอร์ = ตั้งค่า) ใช้เปลี่ยนข้อความและสีของป้าย, `fg` มาจาก **f**ore**g**round (ฟอร์-กราวนด์ = สีตัวอักษร)
- `entry.delete(0, tk.END)` (ดี-ลีต = ลบ, เอนด์ = จุดสุดท้าย) ลบข้อความตั้งแต่ตัวแรกถึงตัวสุดท้าย
- `.focus()` (โฟ-คัส = จุดสนใจ) ย้ายเคอร์เซอร์ไปที่ช่องนั้น พร้อมให้พิมพ์ลูกค้าคนต่อไป

### 5.7 ส่วน GUI

```python
root = tk.Tk()
root.title("คิดเงินทอนร้านค้า")
root.geometry("380x480")
root.resizable(False, False)
```

- `tk.Tk()` สร้างหน้าต่างหลัก เรียกว่า `root` (รูท = ราก) เพราะชิ้นส่วนทุกชิ้นงอกออกมาจากหน้าต่างนี้
- `title` (ไท-เทิล = ชื่อเรื่อง) ข้อความบนแถบด้านบนหน้าต่าง
- `geometry` (จี-ออม-เม-ทรี = เรขาคณิต) ขนาดหน้าต่าง กว้าง x สูง (หน่วย pixel พิก-เซล = จุดบนจอ)
- `resizable(False, False)` (รี-ไซ-ซะ-เบิล = ปรับขนาดได้) ห้ามยืดแนวนอนและแนวตั้ง

```python
price_entry = tk.Entry(root, width=15, font=("Helvetica", 16), justify="center")
price_entry.pack(pady=5)
```

- `Entry` (เอน-ทรี = ช่องกรอก) ช่องให้พิมพ์ 1 บรรทัด
- `justify="center"` (จัส-ติ-ฟาย = จัดแนว, เซน-เตอร์ = ตรงกลาง) ให้ตัวเลขอยู่กลางช่อง
- `.pack()` (แพ็ก = จัดใส่) วางชิ้นส่วนลงหน้าต่างเรียงจากบนลงล่าง, `pady` คือระยะห่าง (**pad**ding แพด-ดิ้ง = ช่องว่างกันชน) แนว **y** (แนวตั้ง)

```python
button_frame = tk.Frame(root)
tk.Button(button_frame, text="คิดเงินทอน", command=on_calculate).pack(side="left", padx=5)
```

- `Frame` (เฟรม = กรอบ) กล่องใส่ปุ่มสองปุ่มให้อยู่แถวเดียวกัน
- `Button` (บัต-ตัน = ปุ่ม), `command=on_calculate` (คอม-มานด์ = คำสั่ง) บอกว่ากดแล้วให้เรียกฟังก์ชันไหน
  - ⚠️ ใส่แค่ชื่อ `on_calculate` **ไม่มีวงเล็บ** เพราะถ้าใส่ `on_calculate()` มันจะทำงานทันทีตอนสร้างปุ่ม แทนที่จะรอให้กด
- `side="left"` (ไซด์ = ด้าน, เลฟต์ = ซ้าย) วางเรียงจากซ้ายไปขวา

```python
root.bind("<Return>", on_calculate)
root.mainloop()
```

- `bind` (ไบนด์ = ผูก) ผูกปุ่ม Enter (บนคีย์บอร์ดเรียกว่า Return รี-เทิร์น) เข้ากับฟังก์ชัน
- `mainloop` (เมน-ลูป = วงวนหลัก) เปิดหน้าต่างค้างไว้และคอยฟังว่าผู้ใช้กดอะไร **ต้องอยู่บรรทัดสุดท้ายเสมอ**

## 6. แนวคิด CS: Greedy Algorithm (อัลกอริทึมแบบละโมบ)

**Greedy** (กรีด-ดี้) แปลว่าละโมบ คือวิธีที่ **ทุกขั้นเลือกตัวที่ดีที่สุด ณ ตอนนั้นทันที** โดยไม่มองไปข้างหน้า

ในโปรแกรมนี้ "ดีที่สุดตอนนั้น" ก็คือ **ใช้แบงก์ใหญ่ที่สุดที่ยังใช้ได้ก่อน** ทำให้ได้จำนวนใบน้อยที่สุด เหมือนแม่ค้าที่หยิบแบงก์ใหญ่ทอนก่อนแล้วค่อยเติมเศษ

**ทำไมต้องเรียงจากมากไปน้อย?** ถ้าเรียงจากน้อยไปมาก `[1, 2, 5, ...]` โปรแกรมจะทอนเหรียญบาทหมดเลย เช่น 1873 บาท ก็จะได้เหรียญ 1 บาท 1873 เหรียญ!

> 💡 **ข้อควรรู้ที่ทำให้ดูเข้าใจลึก:** greedy ได้คำตอบดีที่สุดกับเงินไทย เพราะชนิดเงินไทยถูกออกแบบมาดี แต่ **ไม่ได้ดีที่สุดกับทุกระบบเงิน** เช่น ถ้ามีเหรียญแค่ 1, 3, 4 แล้วจะทอน 6 วิธี greedy จะได้ 4+1+1 = 3 เหรียญ ทั้งที่ 3+3 ใช้แค่ 2 เหรียญ

## 7. คำถามที่กรรมการอาจถาม และแนวตอบ

**Q1: โปรแกรมนี้แก้ปัญหาอะไร?**
> ช่วยร้านค้าในชุมชนคิดเงินทอนเร็วและไม่ผิด และบอกว่าควรทอนแบงก์อะไรเพื่อให้ใช้จำนวนใบน้อยที่สุดครับ

**Q2: `//` กับ `%` ต่างกันยังไง?**
> `//` หารแล้วเอาแค่ผลจำนวนเต็ม เช่น 873 // 500 = 1 ส่วน `%` หารแล้วเอาเศษ เช่น 873 % 500 = 373 ผมใช้ `//` หาว่าใช้แบงก์ได้กี่ใบ และใช้ `%` หาว่าเหลือต้องทอนอีกเท่าไรครับ

**Q3: ถ้าผู้ใช้พิมพ์ตัวหนังสือแทนตัวเลขจะเกิดอะไรขึ้น?**
> ผมตรวจด้วย `.isdigit()` ก่อนแปลงเป็นตัวเลข ถ้าไม่ใช่ตัวเลขจะขึ้นข้อความสีแดงเตือน โปรแกรมไม่พังครับ

**Q4: วิธีคิดแบบนี้เรียกว่าอะไร ใช้ได้กับทุกกรณีไหม?**
> เรียกว่า Greedy algorithm คือเลือกแบงก์ใหญ่สุดก่อนเสมอ ใช้ได้ดีกับเงินไทย แต่ถ้าระบบเหรียญแปลกๆ เช่น 1, 3, 4 อาจไม่ได้คำตอบที่ดีที่สุดครับ

**Q5: ถ้าจะพัฒนาต่อจะเพิ่มอะไร?**
> เช่น รองรับสตางค์ (ทศนิยม) หรือให้ใส่จำนวนแบงก์ที่มีในลิ้นชักจริง แล้วโปรแกรมทอนจากของที่มีอยู่ครับ
