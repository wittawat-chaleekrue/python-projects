# อธิบายโค้ด: ระบบบัตรคิวร้านค้า/คลินิกในชุมชน (queue_system.py)

## 1. โปรแกรมนี้ทำอะไร

- **ออกบัตรคิว**: กดแล้วได้เลขคิว 1, 2, 3, ... ต่อท้ายแถว
- **เรียกคิวถัดไป**: เรียกคนที่อยู่หน้าสุดของแถว แสดงตัวใหญ่บนจอ "เชิญคิวที่ ..."
- **แสดงคนรอ**: บอกว่าเหลือกี่คิว และแต่ละคนต้องรอประมาณกี่นาที
- **ล้างคิว**: เริ่มใหม่ที่คิว 1 (เช่น ตอนเปิดร้านวันใหม่)

**ทำไมทำ (เล่าให้อาจารย์ฟังได้):** ร้านค้าหรือคลินิกเล็กๆ ในชุมชนยังเรียกคิวด้วยปากหรือกระดาษ คนไม่รู้ว่าต้องรออีกนานแค่ไหน ผมเลยทำโปรแกรมเรียกคิวง่ายๆ ที่บอกเวลารอได้ และได้เรียนรู้เรื่อง **คิว (Queue)** ซึ่งเป็นโครงสร้างข้อมูลพื้นฐานของวิทยาการคอมพิวเตอร์

---

## 2. แนวคิดสำคัญ: คิว (Queue) คืออะไร

**Queue** อ่านว่า "คิว" = แถวรอ

กฎของคิวคือ **"มาก่อน ได้ก่อน"** ภาษาอังกฤษเรียกว่า **FIFO** (ฟี-โฟ) มาจาก **First In, First Out** (เฟิร์สท์ อิน เฟิร์สท์ เอาท์ = เข้าก่อน ออกก่อน)

> เปรียบเทียบ: แถวซื้อข้าวที่โรงอาหาร คนมาใหม่ต่อ**ท้าย**แถว คนที่ได้ข้าวคือคน**หน้า**สุด ไม่มีใครแซงได้

ในโปรแกรม เราใช้ list ทำเป็นแถว:
- ต่อท้ายแถว = `waiting.append(เลขคิว)`
- เอาคนหน้าสุดออก = `waiting.pop(0)`

```
เริ่มต้น:           []
ออกคิว 1, 2, 3:     [1, 2, 3]
เรียกคิวถัดไป:      ได้ 1 → เหลือ [2, 3]
ออกคิว 4:           [2, 3, 4]
```

**ของคู่กันที่อาจารย์อาจถาม:** **Stack** (สแต็ก = กองซ้อน) กฎคือ "มาทีหลัง ออกก่อน" (LIFO แอล-ไอ-เอฟ-โอ = Last In, First Out) เหมือนกองจานที่หยิบใบบนสุดก่อน

## 5. อธิบายโค้ดทีละส่วน

### ส่วนหัว

```python
import tkinter as tk
from tkinter import messagebox
```
- นำ tkinter (เครื่องมือสร้างหน้าต่าง) มาใช้ ตั้งชื่อเล่นว่า `tk`
- `messagebox` (เมส-เสจ-บ็อกซ์) = หน้าต่างเด้งแจ้งเตือน

```python
MINUTES_PER_PERSON = 5
```
- `minutes per person` (มิน-นิทส์ เพอร์ เพอร์-ซั่น) = นาทีต่อคน
- สมมติว่าบริการคนละ 5 นาที เขียนตัวใหญ่หมด = ค่าคงที่ (constant) ถ้าร้านไหนบริการนานกว่านี้ แก้เลขที่บรรทัดนี้บรรทัดเดียว ทั้งโปรแกรมเปลี่ยนตาม

```python
waiting = []
next_number = 1
```
- `waiting` = แถวคนรอ ตอนเริ่มว่างเปล่า `[]`
- `next_number` = เลขคิวที่จะแจกคนถัดไป เริ่มที่ 1

> เปรียบเทียบ: `waiting` คือแถวคนจริงๆ, `next_number` คือเลขบนบัตรใบบนสุดของปึกบัตรคิว

### `take_ticket()` — กดปุ่ม "ออกบัตรคิว"

```python
def take_ticket():
    global next_number

    waiting.append(next_number)
    messagebox.showinfo("บัตรคิว", f"คุณได้คิวที่ {next_number}")
    next_number = next_number + 1
    update_screen()
```
1. `global next_number` = บอกว่าจะ**แก้ค่า**ตัวแปร `next_number` ที่อยู่นอกฟังก์ชัน
2. `waiting.append(next_number)` = เอาเลขคิวไปต่อท้ายแถว
3. `showinfo` (โชว์-อิน-โฟ = แสดงข้อมูล) เด้งบอกเลขคิว
4. เลขคิวถัดไป +1 (ฉีกบัตรใบบนออก ใบถัดไปเลขเพิ่ม 1)
5. `update_screen()` = วาดหน้าจอใหม่

**คำถามที่น่าคิด:** ทำไม `waiting` ไม่ต้องใช้ `global`?
เพราะเราไม่ได้ "เปลี่ยน `waiting` เป็น list ใหม่" เราแค่ "ใส่ของเพิ่มลงใน list เดิม" ด้วย `.append()` ซึ่งไม่ต้องประกาศ global แต่ `next_number = next_number + 1` เป็นการ**ใส่ค่าใหม่**ให้ตัวแปร จึงต้องประกาศ

> เปรียบเทียบ: ใส่ของเพิ่มลงกล่องที่วางอยู่หน้าห้อง ใครก็ใส่ได้ แต่ถ้าจะ "เปลี่ยนเลขบนกระดานหน้าห้อง" ต้องขออนุญาตก่อน

### `call_next()` — กดปุ่ม "เรียกคิวถัดไป"

```python
def call_next():
    if len(waiting) == 0:
        messagebox.showinfo("แจ้งเตือน", "ไม่มีคิวรออยู่")
        return

    number = waiting.pop(0)
    label_now.config(text=f"เชิญคิวที่ {number}")
    update_screen()
```
1. `len(waiting) == 0` = ถ้าแถวว่าง (`len` มาจาก length = ความยาว) → เตือนแล้ว `return` ออก
   - **ถ้าไม่เช็คตรงนี้** แล้วไป `pop(0)` บน list ว่าง โปรแกรมจะ **error** (เออ-เร่อ = ข้อผิดพลาด) ทันที
2. `waiting.pop(0)` = ดึงชิ้นที่ตำแหน่ง **0** ออก (ใน Python นับตำแหน่งเริ่มจาก 0 ไม่ใช่ 1 ดังนั้น 0 = หน้าสุด) แล้วเก็บไว้ในตัวแปร `number`
3. เปลี่ยนป้ายตัวใหญ่เป็น "เชิญคิวที่ ..." (`config` = ตั้งค่าใหม่)
4. วาดหน้าจอใหม่

### `reset_queue()` — กดปุ่ม "ล้างคิวทั้งหมด"

```python
sure = messagebox.askyesno("ยืนยัน", "ต้องการล้างคิวทั้งหมด เริ่มใหม่ที่คิว 1 ใช่ไหม?")
if sure:
    waiting.clear()
    next_number = 1
    ...
```
- `askyesno` (อาสก์-เยส-โน = ถาม ใช่/ไม่ใช่) = เด้งถามยืนยัน ถ้ากด "Yes" ได้ `True` (ทรู = จริง) กด "No" ได้ `False` (ฟอลส์ = เท็จ)
- `sure` (ชัวร์ = แน่ใจ) เก็บคำตอบไว้
- ถามก่อนเพราะการล้างคิว**ย้อนกลับไม่ได้** ถ้าเผลอกดจะได้ไม่พัง
- `waiting.clear()` = ล้างแถวให้ว่าง, `next_number = 1` = เริ่มเลข 1 ใหม่

### `update_screen()` — วาดหน้าจอใหม่ (หัวใจของการแสดงผล)

```python
listbox.delete(0, tk.END)

position = 1
for number in waiting:
    wait_time = position * MINUTES_PER_PERSON
    listbox.insert(tk.END, f"ลำดับที่ {position}: คิว {number}  (รอประมาณ {wait_time} นาที)")
    position = position + 1
```
1. ล้างกล่องรายการเดิมทั้งหมด (`delete` ตั้งแต่ 0 ถึง `END` = ตัวสุดท้าย)
2. `position = 1` = เริ่มนับลำดับที่ 1
3. `for number in waiting` = **วนลูป**หยิบเลขคิวในแถวทีละตัว
4. คำนวณเวลารอ = ลำดับ x 5 นาที (`*` คือคูณ) — คนที่ 1 รอ 5 นาที, คนที่ 2 รอ 10 นาที
5. `insert` (อิน-เซิร์ท = แทรก/ใส่) บรรทัดใหม่ต่อท้ายกล่องรายการ
6. ลำดับ +1 ไปคนถัดไป

**ทำไมต้องล้างแล้ววาดใหม่ทุกครั้ง?** เพราะง่ายและไม่พลาด ข้อมูลจริงอยู่ใน `waiting` หน้าจอเป็นแค่ "ภาพสะท้อน" ของข้อมูล ข้อมูลเปลี่ยนเมื่อไหร่ก็วาดภาพใหม่ทั้งหมด

> เปรียบเทียบ: กระดานคะแนนฟุตบอล พอมีประตูเพิ่ม ก็ลบตัวเลขเก่าแล้วเขียนใหม่

```python
total_wait = len(waiting) * MINUTES_PER_PERSON
label_waiting.config(text=f"รออยู่ {len(waiting)} คิว | คนสุดท้ายรอประมาณ {total_wait} นาที")
```
นับจำนวนคนรอ แล้วคำนวณว่าคนสุดท้ายต้องรอนานเท่าไร

## 6. ลำดับการทำงานทั้งหมด

```
เปิดโปรแกรม → แถวว่าง, เลขคิวถัดไป = 1 → รอกดปุ่ม
   ├─ "ออกบัตรคิว"    → ต่อท้ายแถว (append) → เด้งบอกเลข → เลข +1 → วาดจอใหม่
   ├─ "เรียกคิวถัดไป" → แถวว่างไหม? ว่าง: เตือน / ไม่ว่าง: ดึงหน้าสุด (pop(0)) → แสดงตัวใหญ่ → วาดจอใหม่
   └─ "ล้างคิว"      → ถามยืนยัน → ล้างแถว, เลขกลับเป็น 1 → วาดจอใหม่
```

## 7. คำถามที่อาจารย์อาจถาม + แนวตอบ

**ถาม: Queue คืออะไร ต่างจาก Stack ยังไง?**
ตอบ: Queue คือมาก่อนได้ก่อน เหมือนแถวซื้อข้าว ส่วน Stack คือมาทีหลังออกก่อน เหมือนกองจาน ในโปรแกรมผมใช้ Queue เพราะลูกค้าที่มาก่อนต้องได้รับบริการก่อนครับ

**ถาม: ใช้คำสั่งอะไรทำ Queue?**
ตอบ: ใช้ list ครับ เพิ่มคนต่อท้ายด้วย append และเรียกคนหน้าสุดออกด้วย pop(0) ใส่เลข 0 เพราะ Python นับตำแหน่งเริ่มจาก 0

**ถาม: ถ้ากดเรียกคิวตอนไม่มีคนรอจะเกิดอะไรขึ้น?**
ตอบ: ผมเช็คด้วย if ก่อนว่า len(waiting) เท่ากับ 0 ไหม ถ้าใช่จะเตือนแล้วออกจากฟังก์ชัน ถ้าไม่เช็ค pop บน list ว่างจะทำให้โปรแกรม error ครับ

**ถาม: เวลารอคำนวณยังไง แม่นไหม?**
ตอบ: เอาลำดับในแถวคูณ 5 นาที ซึ่งเป็นค่าประมาณที่ผมสมมติ ยังไม่แม่นเพราะแต่ละคนใช้เวลาไม่เท่ากัน ถ้าพัฒนาต่อจะจับเวลาจริงตอนเรียกแต่ละคิว แล้วหาค่าเฉลี่ยมาคำนวณแทนครับ

**ถาม: จุดอ่อนอื่นๆ / จะพัฒนาต่อยังไง?**
- ปิดโปรแกรมแล้วคิวหาย → บันทึกลงไฟล์
- มีช่องบริการแค่ช่องเดียว → รองรับหลายช่อง เช่น "เชิญคิว 5 ที่ช่อง 2"
- `pop(0)` บน list ช้าลงถ้าคนเยอะมากๆ เพราะต้องเลื่อนทุกตัวขึ้นมา → Python มีเครื่องมือ `deque` (เดค) ที่ทำคิวได้เร็วกว่า (รู้ไว้พูดได้ ไม่ต้องใช้จริงก็ได้)
