## 4. อธิบายโค้ดทีละส่วน

### หน้าตาข้อมูล: Graph ⭐

**Graph** = กลุ่มของ **จุด (node)** ที่เชื่อมกันด้วย **เส้น (edge)**
- จุด = สถานที่ในโรงเรียน
- เส้น = ทางเดิน
- **เปรียบเทียบ:** เหมือนแผนที่รถไฟฟ้า ที่มีสถานีเป็นจุด และรางเป็นเส้นเชื่อม

```python
positions = {
    "ประตูหน้า": (70, 340),
    ...
}
```
dict เก็บ **ตำแหน่งบนจอ** ของแต่ละสถานที่ `(70, 340)` คือ **tuple** (ทู-เพิล) คล้าย list แต่ใช้วงเล็บธรรมดาและแก้ไขไม่ได้ เหมาะกับพิกัดที่ไม่เปลี่ยน

```python
paths = [
    ("ประตูหน้า", "ลานจอดรถ"), ("ประตูหน้า", "เสาธง"),
    ...
]
```
list ของทางเดิน แต่ละคู่แปลว่า "2 ที่นี้มีทางเดินถึงกัน"

#### แปลงเป็น "รายชื่อเพื่อนบ้าน" (Adjacency List)
```python
school_map = {}
for place in positions:
    school_map[place] = []
for a, b in paths:
    school_map[a].append(b)
    school_map[b].append(a)
```
- ขั้นแรก ทุกสถานที่เริ่มด้วยลิสต์เพื่อนบ้านว่าง
- `for a, b in paths:` = หยิบทีละคู่ แล้ว **แกะใส่ 2 ตัวแปรพร้อมกัน** เช่น `a = "ประตูหน้า"`, `b = "ลานจอดรถ"`
- ใส่ **ทั้งสองทาง** เพราะทางเดินเดินไป-กลับได้ (เรียกว่า **undirected graph** อัน-ได-เรก-ทิด = กราฟไม่มีทิศทาง)
- ผลลัพธ์ เช่น `school_map["โรงอาหาร"]` → `["อาคาร 2", "หอประชุม", "อาคาร 3", "สนามฟุตบอล"]`
- **เปรียบเทียบ:** เหมือนสมุดที่แต่ละหน้าเขียนว่า "จากที่นี่ เดินไปที่ไหนได้บ้าง"

### ส่วนที่ 1: `bfs(start, goal)` — หัวใจของโปรแกรม ⭐⭐

**แนวคิด BFS:** โยนก้อนหินลงน้ำ คลื่นจะกระจายออกเป็นวง **ชั้นที่ 1** ก่อน แล้วค่อยเป็น **ชั้นที่ 2, 3** …
- สำรวจทุกที่ที่ห่าง **1 ก้าว** ให้หมดก่อน → แล้วค่อยไปที่ห่าง **2 ก้าว** → แล้ว **3 ก้าว** …
- ดังนั้น **ครั้งแรกที่ไปถึงปลายทาง ย่อมเป็นทางที่ใช้ก้าวน้อยที่สุดแน่นอน** (เพราะทางที่สั้นกว่าถูกสำรวจไปหมดก่อนแล้ว)

```python
queue = [start]
came_from = {start: None}
```
- `queue` = แถวคอยของจุดที่รอสำรวจ ใช้หลัก **Queue / FIFO** เหมือนโปรเจค queue_system เลย!
- `came_from` = dict จำว่า "มาถึงจุดนี้จากจุดไหน" ต้นทางไม่ได้มาจากไหน จึงเป็น `None`
- `came_from` ทำ 2 หน้าที่พร้อมกัน: **(1)** เช็คว่าเคยไปจุดนี้แล้วหรือยัง **(2)** ใช้ย้อนรอยหาเส้นทางตอนท้าย

```python
while len(queue) > 0:
    current = queue.pop(0)
    if current == goal:
        break
    for neighbor in school_map[current]:
        if neighbor not in came_from:
            came_from[neighbor] = current
            queue.append(neighbor)
```
อ่านเป็นภาษาคน:
1. ตราบใดที่ยังมีจุดรอสำรวจ…
2. หยิบจุดที่ **รอนานที่สุด** (หัวคิว) ออกมา
3. ถ้าเป็นปลายทาง → หยุด (`break` = เบรก = หยุด loop)
4. ไม่ใช่ → ดูเพื่อนบ้านทุกตัวของจุดนี้ ถ้ายังไม่เคยไป → จดว่ามาจาก current แล้วต่อท้ายคิว

#### ลองทำด้วยมือ: จาก "ลานจอดรถ" ไป "โรงอาหาร"

| รอบ | หยิบออก (current) | เพื่อนบ้านใหม่ที่ใส่คิว | คิวหลังจบรอบ |
|---|---|---|---|
| 1 | ลานจอดรถ | ประตูหน้า, อาคาร 1 | [ประตูหน้า, อาคาร 1] |
| 2 | ประตูหน้า | เสาธง | [อาคาร 1, เสาธง] |
| 3 | อาคาร 1 | ห้องสมุด (เสาธงเคยจดแล้ว) | [เสาธง, ห้องสมุด] |
| 4 | เสาธง | อาคาร 2, หอประชุม | [ห้องสมุด, อาคาร 2, หอประชุม] |
| 5 | ห้องสมุด | อาคาร 3 | [อาคาร 2, หอประชุม, อาคาร 3] |
| 6 | อาคาร 2 | **โรงอาหาร** (มาจากอาคาร 2) | [หอประชุม, อาคาร 3, โรงอาหาร] |
| … | … จนหยิบโรงอาหารออกมา → break | | |

สังเกตว่าคิวมีแต่ **ชั้น 1 → ชั้น 2 → ชั้น 3** เรียงกันเสมอ นี่คือเหตุผลที่ต้องใช้ Queue

#### ย้อนรอยหาเส้นทาง
```python
route = []
place = goal
while place is not None:
    route.append(place)
    place = came_from[place]
route.reverse()
```
- เริ่มจากปลายทาง ถาม `came_from` ว่า "มาจากไหน" ไปเรื่อย ๆ จนเจอ `None` (ถึงต้นทาง)
- ได้ `[โรงอาหาร, อาคาร 2, เสาธง, ประตูหน้า, ลานจอดรถ]` (กลับหัว) → `reverse()` กลับลำดับให้ถูก
- **เปรียบเทียบ:** เหมือน **นิทานฮันเซลกับเกรเทล** ที่โรยเศษขนมปังไว้ แล้วเดินตามเศษขนมปังย้อนกลับบ้าน

```python
if goal not in came_from:
    return None
```
ถ้าสำรวจหมดคิวแล้วยังไม่เคยจดปลายทาง แปลว่า **ไม่มีทางไปถึง**

### ส่วนที่ 2: วาดแผนที่ + ปุ่ม

#### `draw_map(route)` วาด 3 ชั้น
1. **เส้นทางเดินทั้งหมด** สีเทา
2. **เส้นทางที่หาได้** สีแดงหนา ทับข้างบน — วนตั้งแต่ `i = 0` ถึง `len(route) - 2` แล้ววาดเส้นจาก `route[i]` ไป `route[i + 1]` (ต้องลบ 1 เพราะ 5 จุดมีเส้นเชื่อมแค่ 4 เส้น)

```python
x1, y1 = positions[a]
```
แกะ tuple `(70, 340)` ใส่ 2 ตัวแปรพร้อมกัน → `x1 = 70`, `y1 = 340`

- `" → ".join(route)` ต่อชื่อในลิสต์ คั่นด้วยลูกศร

- จำนวนช่วงทาง = `len(route) - 1` (จุด 5 จุด เดิน 4 ช่วง)

## 5. ลำดับการทำงานทั้งหมด

```
เปิดโปรแกรม → สร้าง Graph จาก paths (ใส่เพื่อนบ้านทั้ง 2 ทาง) → วาดแผนที่เปล่า → รอ
   └─ "หาเส้นทาง" → ต้นทาง = ปลายทาง? เตือน
                  → BFS: คิว = [ต้นทาง]
                       วน while คิวไม่ว่าง:
                          หยิบหัวคิว → ถึงปลายทาง? หยุด
                          เพื่อนบ้านที่ยังไม่เคยไป → จด came_from → ต่อท้ายคิว
                  → ย้อนรอย came_from จากปลายทาง → reverse
                  → วาดเส้นสีแดง + แสดงลำดับสถานที่
```

## 6. คำถามที่อาจารย์อาจถาม + แนวตอบ

**ถาม: Graph คืออะไร?**
ตอบ: โครงสร้างข้อมูลที่มีจุด (node) กับเส้นเชื่อม (edge) ครับ ใช้แทนอะไรก็ได้ที่ "เชื่อมกัน" เช่น แผนที่ถนน เพื่อนใน Facebook หรือหน้าเว็บที่ลิงก์หากัน ในโปรแกรมผม จุดคือสถานที่ เส้นคือทางเดิน

**ถาม: เก็บ Graph ในโปรแกรมยังไง?**
ตอบ: ใช้ **Adjacency List** (แอด-จา-เซน-ซี ลิสต์ = รายชื่อเพื่อนบ้าน) ครับ เป็น dict ที่คีย์คือสถานที่ ค่าคือลิสต์ของสถานที่ที่เดินไปถึงได้ อีกวิธีคือ **Adjacency Matrix** เป็นตาราง 2 มิติ ช่องไหนเป็น 1 แปลว่าเชื่อมกัน แต่เปลืองที่ถ้าจุดเยอะและเส้นน้อย

**ถาม: ทำไม BFS ได้เส้นทางที่สั้นที่สุด?**
ตอบ: เพราะ BFS สำรวจทีละชั้นครับ ทุกจุดที่ห่าง 1 ก้าวถูกสำรวจหมดก่อน แล้วค่อย 2 ก้าว ดังนั้นครั้งแรกที่เจอปลายทาง ก็ต้องเป็นจำนวนก้าวที่น้อยที่สุดแล้ว

**ถาม: ทำไมต้องใช้ Queue? ใช้ Stack ได้ไหม?**
ตอบ: ต้องใช้ Queue ครับ เพราะเข้าก่อน-ออกก่อนทำให้จุดชั้นใกล้ถูกสำรวจก่อนชั้นไกล ถ้าเปลี่ยนเป็น Stack (เข้าทีหลัง-ออกก่อน) จะกลายเป็นอีกอัลกอริทึมชื่อ **DFS** (Depth-First Search = ค้นลงลึกก่อน) ซึ่งเจอทางเหมือนกัน แต่ไม่รับประกันว่าสั้นที่สุด

**ถาม: ถ้าไม่มี `came_from` เช็คว่าเคยไปแล้ว จะเกิดอะไรขึ้น?**
ตอบ: จะวนไม่จบครับ เพราะทางเดินเป็นสองทาง ประตูหน้าจะใส่เสาธง เสาธงก็ใส่ประตูหน้ากลับเข้าคิวอีก วนไปมาเรื่อย ๆ

**ถาม: BFS ได้ทางที่ "ใกล้ที่สุดเป็นเมตร" ไหม?**
ตอบ: ไม่ครับ BFS นับแค่ **จำนวนช่วงทาง** ถือว่าทุกเส้นยาวเท่ากัน ถ้าทางเดินยาวไม่เท่ากัน ต้องใส่ระยะทางเป็น "น้ำหนัก" ของเส้น แล้วใช้อัลกอริทึม **Dijkstra (ไดก์-สตรา)** แทน ซึ่ง Google Maps ใช้แนวคิดนี้ร่วมกับเทคนิคอื่น

**ถาม: ความเร็วของ BFS เป็นเท่าไร?**
ตอบ: O(V + E) ครับ คือแต่ละจุด (V = vertex) เข้าคิวแค่ครั้งเดียว และแต่ละเส้น (E = edge) ถูกดูไม่เกินสองครั้ง

## 7. จุดอ่อนและวิธีพัฒนาต่อ

- **ไม่คิดระยะทางจริง** → ใส่ระยะ (เมตร) ให้แต่ละเส้น แล้วใช้ Dijkstra
- **`queue.pop(0)` ช้าถ้าข้อมูลเยอะ** เพราะต้องเลื่อนทุกตัวในลิสต์ → ใช้ `collections.deque` ที่ `popleft()` ได้เร็ว
- **แผนที่เป็นสถานที่สมมติ** → แก้ให้เป็นอาคารจริงของโรงเรียน (ทำเองได้เลย แค่แก้ `positions` กับ `paths`)
- **ปิดทางเดินชั่วคราวไม่ได้** (เช่น ทางซ่อม) → เพิ่มให้คลิกที่เส้นเพื่อปิด แล้วหาทางใหม่
- **ไม่บอกว่าเดินกี่นาที** → คำนวณจากระยะทาง ÷ ความเร็วเดิน

## 8. แบบฝึก (ทำเองก่อนดูโค้ด)

1. **ทำมือบนกระดาษ:** วาดแผนที่จากโค้ด แล้วทำ BFS จาก `ห้องสมุด` ไป `ประตูหน้า` เขียนตารางคิวทุกรอบเหมือนตัวอย่าง แล้วเทียบกับโปรแกรม
