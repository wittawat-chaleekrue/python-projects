## 1. โปรแกรมนี้ทำอะไร

**ปัญหา:** ร้านขายของชำในชุมชนหลายร้านยังจดรายรับ-รายจ่ายในสมุด ทำให้
- รวมยอดยาก ต้องกดเครื่องคิดเลขเอง
- ไม่รู้ว่าเดือนนี้ **กำไรหรือขาดทุน**
- จดผิดแล้วแก้ยาก สมุดหายข้อมูลก็หายหมด

**โปรแกรมช่วยได้อย่างนี้:**
1. บันทึกรายการ (วันที่ / รายรับหรือรายจ่าย / รายละเอียด / จำนวนเงิน)
2. **แก้ไข** และ **ลบ** รายการที่จดผิดได้
3. สรุป **รายรับรวม รายจ่ายรวม กำไร/ขาดทุน** ให้อัตโนมัติ
4. กรองดูเฉพาะเดือนที่ต้องการได้
5. ข้อมูลเก็บในไฟล์ฐานข้อมูล `shop.db` ปิดโปรแกรมแล้วข้อมูลไม่หาย

- `messagebox` (เมสเสจ บ็อกซ์ = กล่องข้อความ) คือหน้าต่างเล็กที่เด้งขึ้นมาเตือนหรือถามยืนยัน
- `sqlite3` คือเครื่องมือคุยกับฐานข้อมูล SQLite (เลข 3 คือเวอร์ชัน)
- `datetime` (เดตไทม์ = วันที่และเวลา) ในโค้ดนี้ใช้ `date` สำหรับวันที่วันนี้ และ `datetime` สำหรับตรวจรูปแบบวันที่

```python
DB_FILE = "shop.db"
```
- `DB` ย่อมาจาก **D**ata**b**ase ส่วน `.db` คือนามสกุลไฟล์ฐานข้อมูล

### 5.2 ส่วนที่ 1: เปิดฐานข้อมูลและสร้างตาราง

```python
conn = sqlite3.connect(DB_FILE)
cur = conn.cursor()
```
- `connect` (คอนเน็กต์ = เชื่อมต่อ) เปิดไฟล์ฐานข้อมูล ถ้ายังไม่มีไฟล์ จะ **สร้างใหม่ให้อัตโนมัติ**
- `conn` ย่อมาจาก **conn**ection (คอนเน็กชัน = การเชื่อมต่อ)
- `cur` ย่อมาจาก **cur**sor เป็นตัวที่เราใช้ส่งคำสั่ง SQL

**เปรียบเทียบ:** `conn` คือ **การเปิดประตูห้องเก็บเอกสาร** ส่วน `cur` คือ **พนักงานในห้อง** ที่เราสั่งให้หยิบหรือเขียนเอกสาร

```python
cur.execute("""
    CREATE TABLE IF NOT EXISTS records (
        id      INTEGER PRIMARY KEY AUTOINCREMENT,
        date    TEXT,
        kind    TEXT,
        detail  TEXT,
        amount  REAL
    )
""")
conn.commit()
```
- `execute` (เอ็กซิคิวต์ = ดำเนินการ) คือสั่งให้ทำคำสั่ง SQL
- `"""...."""` (อัญประกาศสามตัว) คือข้อความยาวหลายบรรทัด
- **อ่านคำสั่ง SQL เป็นภาษาคน:** "**สร้างตาราง**ชื่อ `records` **ถ้ายังไม่มี** โดยมีคอลัมน์..."
  - `CREATE TABLE` (ครีเอต เทเบิล) = สร้างตาราง
  - `IF NOT EXISTS` (อิฟ น็อต เอ็กซิสต์ส) = ถ้ายังไม่มีอยู่ ใส่ไว้กันพัง เพราะเปิดโปรแกรมครั้งที่ 2 ตารางมีอยู่แล้ว จะได้ไม่สร้างซ้ำ
  - `records` (เรคคอร์ดส์) = ชื่อตาราง แปลว่า "รายการบันทึก"

| คอลัมน์ | ชนิดข้อมูล | ความหมาย |
|---|---|---|
| `id` | `INTEGER` (อินทีเจอร์ = จำนวนเต็ม) | เลขประจำรายการ |
| `date` | `TEXT` (เท็กซ์ = ข้อความ) | วันที่ เช่น `2026-10-17` |
| `kind` | `TEXT` | "รายรับ" หรือ "รายจ่าย" |
| `detail` | `TEXT` | รายละเอียด เช่น "ขายน้ำแข็ง" |
| `amount` | `REAL` (เรียล = จำนวนจริง มีทศนิยมได้) | จำนวนเงิน |

- `PRIMARY KEY` (ไพรมารี คีย์ = กุญแจหลัก) คือค่าที่ **ห้ามซ้ำ** ใช้ระบุรายการแต่ละแถว เหมือน **เลขประจำตัวนักเรียน** ที่ชื่ออาจซ้ำกันได้ แต่เลขประจำตัวไม่มีวันซ้ำ
- `AUTOINCREMENT` (ออโต้ อินครีเมนต์ = เพิ่มขึ้นอัตโนมัติ) ทำให้ฐานข้อมูลใส่เลข 1, 2, 3, ... ให้เอง
- `conn.commit()` คือ **ยืนยันบันทึกจริง** เหมือนกด Save ถ้าไม่ commit การเปลี่ยนแปลงอาจหายไป

### 5.3 ส่วนที่ 2: ฟังก์ชัน `read_form` (อ่านและตรวจข้อมูลที่กรอก ⭐)

```python
def read_form():
    date_text = date_entry.get().strip()
    kind = kind_var.get()
    detail = detail_entry.get().strip()
    amount_text = amount_entry.get().strip()
```
- อ่านค่าจากทุกช่อง
- `.strip()` (สตริป = ปอกออก) ตัดช่องว่างหัวท้ายทิ้ง เช่น `"  100 "` จะกลายเป็น `"100"`

**ตรวจวันที่:**
```python
    try:
        datetime.strptime(date_text, "%Y-%m-%d")
    except ValueError:
        messagebox.showwarning("ข้อมูลผิด", "วันที่ต้องเป็นรูปแบบ ปปปป-ดด-วว เช่น 2026-10-17")
        return None
```
- `try` (ทราย = ลอง) / `except` (เอ็กเซ็ปต์ = ยกเว้น) ใช้ **ลองทำ ถ้าพังให้ทำอีกอย่างแทน** โปรแกรมจะได้ไม่ค้างหรือปิดตัวเอง
  - เปรียบเหมือน **ลองเสียบปลั๊ก ถ้าไฟไม่ติดก็แจ้งว่าปลั๊กเสีย** แทนที่จะให้บ้านไฟดับทั้งหลัง
- `strptime` ย่อมาจาก **str**ing **p**arse **time** (สตริง พาร์ส ไทม์ = แปลงข้อความเป็นเวลา)
  - `%Y` = ปี 4 หลัก (**Y**ear), `%m` = เดือน (**m**onth), `%d` = วัน (**d**ay)
  - ถ้าแปลงไม่ได้ เช่น กรอก `2026-13-40` (ไม่มีเดือน 13) จะเกิด `ValueError` (แวลู เออเรอร์ = ค่าผิดพลาด) แล้วเข้าส่วน `except`
- `showwarning` (โชว์ วอร์นิง = แสดงคำเตือน)
- `return None` คือส่งค่า "ไม่มีอะไร" กลับไป เพื่อบอกฟังก์ชันที่เรียกว่า "ข้อมูลไม่ผ่าน อย่าบันทึก"

**ตรวจจำนวนเงิน:**
```python
    try:
        amount = float(amount_text)
    except ValueError:
        ...
    if amount <= 0:
        ...
```
- `float` (โฟลต = ลอย มาจาก "จุดทศนิยมลอยตัว") แปลงข้อความเป็นตัวเลขทศนิยม เช่น `"25.50"` เป็น `25.5`
- ถ้ากรอก `"abc"` จะแปลงไม่ได้ จึงแจ้งเตือน
- ถ้ากรอกติดลบหรือ 0 ก็ไม่ยอมเช่นกัน

```python
    return date_text, kind, detail, amount
```
- ถ้าผ่านทุกด่าน ส่งข้อมูลทั้ง 4 อย่างกลับไป

### 5.5 ส่วนที่ 3: CRUD

#### 🔵 R = Read: `load_data` (อ่านข้อมูล + สรุปยอด)

```python
def load_data():
    for row in table.get_children():
        table.delete(row)
```
- ลบทุกแถวในตารางบนหน้าจอก่อน (ลบแค่ **บนหน้าจอ** ไม่ใช่ในฐานข้อมูล) เพื่อไม่ให้ข้อมูลซ้ำซ้อนเวลาโหลดใหม่
- `get_children` (เก็ท ชิลเดรน = เอาลูก ๆ มา) คือทุกแถวในตาราง

```python
    month = month_entry.get().strip()
    if month == "":
        cur.execute("SELECT * FROM records ORDER BY date DESC")
    else:
        cur.execute("SELECT * FROM records WHERE date LIKE ? ORDER BY date DESC",
                    (month + "%",))
    rows = cur.fetchall()
```
**อ่าน SQL เป็นภาษาคน:**
- `SELECT *` (ซีเล็กต์ สตาร์) แปลว่า **เลือกทุกคอลัมน์** (`*` = ทั้งหมด)
- `FROM records` (ฟรอม) แปลว่า **จากตาราง records**
- `ORDER BY date DESC` (ออร์เดอร์ บาย ... เดสก์) แปลว่า **เรียงตามวันที่ จากใหม่ไปเก่า** (`DESC` = **desc**ending = มากไปน้อย)
- `WHERE date LIKE ?` (แวร์ ... ไลก์) แปลว่า **เฉพาะแถวที่วันที่ขึ้นต้นเหมือน...**
  - ถ้าผู้ใช้กรอก `2026-10` จะได้ `"2026-10%"` โดย `%` แปลว่า "ตามด้วยอะไรก็ได้" จึงได้ทุกวันในเดือนตุลาคม 2026
- `fetchall()` (เฟ็ตช์ ออล = ไปเอามาทั้งหมด) ได้ผลเป็น list ของแถว

> 🔐 **เครื่องหมาย `?` สำคัญมาก (จุดเด่นด้านความปลอดภัย!)**
> เราไม่เอาข้อความของผู้ใช้ไป **ต่อเข้าไปในคำสั่ง SQL ตรง ๆ** แต่ใส่ `?` ไว้ แล้วส่งค่าแยกไปต่างหาก
> ถ้าต่อตรง ๆ ผู้ไม่หวังดีอาจพิมพ์คำสั่ง SQL แฝงเข้ามาเพื่อลบหรือขโมยข้อมูล การโจมตีแบบนี้เรียกว่า **SQL Injection** (เอสคิวแอล อินเจ็กชัน = การฉีดคำสั่งเข้าไป) และเป็นช่องโหว่ที่พบบ่อยที่สุดอันดับต้น ๆ ของโลก
> การใช้ `?` เรียกว่า **parameterized query** (พารามิเตอร์ไรซ์ เควียรี) ซึ่งเป็นวิธีป้องกันมาตรฐาน **ประเด็นนี้ควรพูดตอนสัมภาษณ์** เพราะโยงกับความสนใจด้านความปลอดภัยของคุณ

- `(month + "%",)` มี **ลูกน้ำต่อท้าย** เพราะ Python ต้องการ **tuple** (ทูเพิล = ชุดข้อมูลที่แก้ไม่ได้ เขียนใน `( )`) ถ้ามีค่าเดียวต้องใส่ `,` ไม่งั้น Python จะเข้าใจว่าเป็นวงเล็บธรรมดา

```python
    total_income = 0
    total_expense = 0

    for r in rows:
        record_id, d, kind, detail, amount = r
        table.insert("", tk.END, values=(record_id, d, kind, detail, f"{amount:,.2f}"),
                     tags=(kind,))
        if kind == "รายรับ":
            total_income = total_income + amount
        else:
            total_expense = total_expense + amount
```
- `total` (โททัล = ผลรวม) เริ่มที่ 0 แล้ว **สะสมไปทีละแถว** เหมือนการกดเครื่องคิดเลขบวกไปเรื่อย ๆ
- `record_id, d, kind, detail, amount = r` คือ **แกะ** แถว 1 แถว (มี 5 ช่อง) ใส่ตัวแปร 5 ตัว
- `table.insert(...)` เพิ่มแถวลงตารางบนหน้าจอ
- `f"{amount:,.2f}"` จัดรูปแบบตัวเลข
  - `,` ใส่ลูกน้ำคั่นหลักพัน
  - `.2f` แสดงทศนิยม 2 ตำแหน่ง (f = **f**loat)
  - เช่น `1500` จะแสดงเป็น `1,500.00`
- `tags=(kind,)` (แท็กส์ = ป้ายติด) ติดป้าย "รายรับ" หรือ "รายจ่าย" ไว้กับแถว ใช้กำหนดสีพื้นหลัง (เขียว/แดง)

```python
    profit = total_income - total_expense
    ...
    if profit >= 0:
        profit_label.config(text=f"กำไร: {profit:,.2f} บาท", fg="green")
    else:
        profit_label.config(text=f"ขาดทุน: {-profit:,.2f} บาท", fg="red")
```
- **กำไร = รายรับ − รายจ่าย**
- ถ้าติดลบ แปลว่าขาดทุน ใส่ `-profit` เพื่อทำให้เป็นบวกก่อนแสดง เช่น ขาดทุน 400 บาท (แทนที่จะเขียนว่า "ขาดทุน -400")

#### 🟢 C = Create: `add_record`

```python
def add_record():
    data = read_form()
    if data is None:
        return
    cur.execute("INSERT INTO records (date, kind, detail, amount) VALUES (?, ?, ?, ?)",
                data)
    conn.commit()
    clear_form()
    load_data()
```
**ลำดับ:** อ่านฟอร์ม → ถ้าผิดให้หยุด → บันทึก → ยืนยัน → ล้างฟอร์ม → โหลดตารางใหม่
- `is None` คือถามว่า "เป็นค่าว่างไหม?" (ถ้า `read_form` คืน None แปลว่าข้อมูลไม่ผ่าน)
- **SQL:** `INSERT INTO records (...) VALUES (?, ?, ?, ?)` (อินเสิร์ต อินทู ... แวลูส์) แปลว่า **ใส่ข้อมูลเข้าตาราง records** ในคอลัมน์เหล่านี้ ด้วยค่าเหล่านี้
- ไม่ต้องใส่ `id` เพราะ AUTOINCREMENT ใส่ให้เอง
- `?` ทั้ง 4 ตัวจะถูกแทนด้วยค่า 4 ค่าใน `data` ตามลำดับ

#### 🟡 U = Update: `update_record`

```python
    cur.execute("UPDATE records SET date=?, kind=?, detail=?, amount=? WHERE id=?",
                (d, kind, detail, amount, record_id))
```
- **SQL:** `UPDATE records SET ... WHERE id=?` (อัปเดต ... เซ็ต ... แวร์) แปลว่า **แก้ตาราง records โดยตั้งค่าใหม่ เฉพาะแถวที่ id ตรงกัน**
- ⚠️ **ห้ามลืม `WHERE`** ถ้าลืม คำสั่งจะแก้ **ทุกแถวในตาราง** ให้เหมือนกันหมด ซึ่งเป็นความผิดพลาดคลาสสิกของโปรแกรมเมอร์

#### 🔴 D = Delete: `delete_record`

```python
    if messagebox.askyesno("ยืนยัน", "ต้องการลบรายการนี้ใช่ไหม?"):
        cur.execute("DELETE FROM records WHERE id=?", (record_id,))
```
- `askyesno` (อาสก์ เยส โน = ถาม ใช่/ไม่ใช่) เด้งถามยืนยันก่อน ถ้ากด "ใช่" จะได้ `True`
- ถามยืนยันเพราะ **การลบย้อนกลับไม่ได้** ซึ่งเป็นหลักการออกแบบที่ดี
- **SQL:** `DELETE FROM records WHERE id=?` (ดีลีต ฟรอม) แปลว่า **ลบจากตาราง records เฉพาะแถวที่ id ตรงกัน**

#### `on_select` (คลิกแถวแล้วข้อมูลขึ้นในช่องกรอก)

```python
def on_select(event):
    selected = table.selection()
    if len(selected) == 0:
        return
    record_id, d, kind, detail, amount = table.item(selected[0], "values")
    ...
    amount_entry.insert(0, amount.replace(",", ""))
```
- เมื่อผู้ใช้คลิกแถว ให้ดึงค่ามาใส่ช่องกรอก **เพื่อแก้ไขได้ง่าย**
- `.replace(",", "")` (รีเพลซ = แทนที่) เอาลูกน้ำออก เพราะตารางแสดง `1,500.00` แต่ `float()` แปลงข้อความที่มีลูกน้ำไม่ได้

### 5.6 ส่วนที่ 4: หน้าต่าง (GUI)

```python
style = ttk.Style()
```

**จัดวางด้วย `grid`** (กริด = ตาราง) ในส่วนช่องกรอก:

- `pack` วางเรียงทีละอัน ส่วน `grid` วางเป็น **ตาราง แถว/คอลัมน์** เหมาะกับฟอร์มที่มีป้ายอยู่ซ้ายและช่องกรอกอยู่ขวา
- `sticky="w"` (สติกกี = เหนียว ติด) ให้ชิดทิศ **w**est (เวสต์ = ทิศตะวันตก = ซ้าย)
- `columnspan=4` (คอลัมน์สแปน) ให้ช่องนี้กว้างคร่อม 4 คอลัมน์

**ปุ่มเลือก รายรับ/รายจ่าย:**

- `Radiobutton` (เรดิโอ บัตทั่น) คือปุ่มกลมที่ **เลือกได้ทีละอันเดียว** ชื่อมาจากปุ่มเลือกสถานีในวิทยุรุ่นเก่า (กดอันหนึ่ง อีกอันเด้งขึ้น)
- `StringVar` (สตริง วาร์ = ตัวแปรข้อความ) ใช้เก็บค่าที่ถูกเลือก ปุ่มทั้งสองใช้ตัวแปรเดียวกัน จึงเลือกได้แค่อันเดียว

**ตาราง (Treeview):**
```python
columns = ("id", "date", "kind", "detail", "amount")
```

- `Treeview` (ทรีวิว = มุมมองแบบต้นไม้) จริง ๆ ทำเป็นโครงสร้างต้นไม้ได้ แต่เราใช้เป็นตารางธรรมดา
- `show="headings"` แสดงเฉพาะหัวคอลัมน์ (heading เฮดดิง = หัวเรื่อง)
- `anchor` (แองเคอร์ = สมอเรือ) คือการจัดชิด: `"center"` ชิดกลาง, `"e"` ชิดขวา (**e**ast ทิศตะวันออก) ตัวเลขเงินชิดขวาจะอ่านง่าย
- `tag_configure` กำหนดสีแถวตามป้าย โดย `#e3f6e3` คือ **รหัสสี** (เขียวอ่อน)
- `<<TreeviewSelect>>` คือเหตุการณ์ "มีการเลือกแถว" ผูกกับ `on_select`

## 7. คำถามที่กรรมการอาจถาม และแนวตอบ

> ⚠️ ใช้เป็นไอเดีย ให้ตอบด้วยคำพูดของตัวเองตามที่เข้าใจจริง

**Q: ทำไมเลือกทำโปรเจกต์นี้?**
แนวตอบ: เห็นร้านค้าในชุมชนยังจดบัญชีในสมุด อยากใช้คอมพิวเตอร์ช่วยคนในท้องถิ่น (ถ้ามีร้านที่รู้จักจริง ให้เล่าเรื่องจริง ถ้าไม่มี อย่าแต่งเรื่อง)

**Q: ข้อมูลเก็บที่ไหน? ปิดโปรแกรมแล้วหายไหม?**
แนวตอบ: เก็บในฐานข้อมูล SQLite ไฟล์ `shop.db` ไม่หาย เพราะเขียนลงไฟล์ทุกครั้งที่ `commit`

**Q: CRUD คืออะไร? อยู่ตรงไหนในโปรแกรม?**
แนวตอบ: C = `add_record` (INSERT), R = `load_data` (SELECT), U = `update_record` (UPDATE), D = `delete_record` (DELETE)

**Q: ถ้าผู้ใช้กรอกตัวหนังสือในช่องจำนวนเงินจะเกิดอะไรขึ้น?**
แนวตอบ: `float()` แปลงไม่ได้ เกิด ValueError แล้ว `try/except` จับไว้ แจ้งเตือนผู้ใช้ และไม่บันทึก โปรแกรมไม่พัง

**Q: `?` ในคำสั่ง SQL มีไว้ทำไม?**
แนวตอบ: ป้องกัน SQL Injection (อธิบายตามกล่องในข้อ 5.5)

**Q: PRIMARY KEY คืออะไร?**
แนวตอบ: ค่าที่ห้ามซ้ำ ใช้ระบุแต่ละแถว เหมือนเลขประจำตัวนักเรียน ใช้ตอนแก้ไขหรือลบให้ถูกแถว

**Q: ข้อจำกัด / ถ้าพัฒนาต่อ?**
- ตอนนี้ต้องพิมพ์วันที่เอง ควรมีปฏิทินให้คลิกเลือก
- เพิ่มกราฟแสดงรายรับ-รายจ่ายรายเดือน
- ส่งออกเป็นไฟล์ Excel
- มีระบบล็อกอิน (login) กันคนอื่นแก้ข้อมูล
- ทำเป็นแอปมือถือ เพราะแม่ค้าไม่ได้นั่งหน้าคอมตลอด
