# อธิบายโค้ด: โปรแกรมสมุดเบอร์โทรหมู่บ้าน (phone_search.py)

## 1. โปรแกรมนี้ทำอะไร

- มี **สมุดเบอร์โทร** ของคนและสถานที่สำคัญในหมู่บ้าน เช่น ผู้ใหญ่บ้าน อสม. รพ.สต. กู้ภัย ช่างไฟ (เบอร์ในโปรแกรมเป็นเบอร์สมมติ)
- **พิมพ์ชื่อแล้วค้นหา** → ได้เบอร์โทร
- โปรแกรมจะค้นหา **2 วิธีพร้อมกัน** แล้วบอกว่าแต่ละวิธีใช้กี่ขั้น
  - **Linear Search** = ไล่ดูทีละรายชื่อตั้งแต่คนแรก
  - **Binary Search** = เปิดตรงกลาง แล้วตัดทิ้งทีละครึ่ง
- **คลิกชื่อในรายการ** → ชื่อจะเข้าไปอยู่ในช่องค้นหาให้เอง
- **เพิ่มรายชื่อใหม่** ได้ (ถ้าชื่อซ้ำจะเตือน)

**ทำไมทำ (เล่าให้อาจารย์ฟังได้):** ในหมู่บ้านมักมีเบอร์สำคัญเขียนติดไว้บนกระดาษ เวลาฉุกเฉินหาไม่เจอ ผมเลยทำสมุดเบอร์ที่ค้นได้ทันที และใช้โอกาสนี้ทดลองเทียบวิธีค้นหา 2 แบบ ว่าทำไมการเรียงข้อมูลก่อนถึงทำให้ค้นหาเร็วขึ้นมาก โปรเจคนี้ต่อจาก **score_ranking** (เรียงข้อมูล) และ **guess_number** (ที่ผู้เล่นใช้วิธีแบ่งครึ่งด้วยหัวตัวเอง ครั้งนี้ผมเขียนให้คอมพิวเตอร์ทำเอง)

- `ตำรวจ` (ไม่มีในสมุด) → Linear ใช้ 16 ขั้น, Binary ใช้แค่ 4 ขั้นก็รู้แล้วว่าไม่มี

## 4. อธิบายโค้ดทีละส่วน

### หน้าตาข้อมูล

```python
contacts = [
    ["ผู้ใหญ่บ้าน", "081-000-0001"],
    ["อสม.หมู่ 1", "081-000-0002"],
    ...
]
```
เป็น **list ของ list** (list ซ้อน list) 1 รายชื่อเป็น list เล็ก 2 ช่อง:
- `person[0]` = ชื่อ
- `person[1]` = เบอร์โทร

(ครั้งก่อน ๆ ใช้ dictionary แต่ครั้งนี้ใช้ list เพราะทำให้ `sort()` เรียงตามชื่อได้ทันที ดูข้อถัดไป)

```python
contacts.sort()
```
**ครั้งนี้ใช้ `sort()` สำเร็จรูป** (โปรเจคที่แล้วเขียน Bubble Sort เองไปแล้ว ตอนนี้เข้าใจแล้วว่าข้างในทำอะไร จึงใช้ของสำเร็จที่เร็วกว่าได้)
- list ของ list จะถูกเรียงตาม**ช่องแรก** (ชื่อ) ก่อน
- **สำคัญมาก:** Binary Search ใช้ได้กับข้อมูลที่**เรียงแล้วเท่านั้น!**

**⚠️ ข้อสังเกตเรื่องภาษาไทย:** ในรายการ จะเห็น `โรงเรียน` กับ `ไปรษณีย์` ไปอยู่ท้ายสุด ไม่เหมือนพจนานุกรม เพราะ Python เรียงข้อความตาม **รหัสตัวอักษร** ในคอมพิวเตอร์ (เรียกว่า Unicode ยู-นิ-โค้ด = ระบบตัวเลขประจำตัวอักษรทุกภาษา) และสระหน้า `เ แ โ ใ ไ` มีรหัสมากกว่าพยัญชนะทุกตัว
→ **แต่ไม่เป็นไร!** เพราะตอนเรียง (`sort`) และตอนเทียบในการค้นหา (`<`) ใช้กฎเดียวกัน Binary Search จึงยังหาถูกเสมอ

### ส่วนที่ 1: การค้นหา 2 แบบ ⭐

#### แบบที่ 1: `linear_search()` — ไล่ทีละคน

```python
def linear_search(name):
    steps = 0
    for person in contacts:
        steps = steps + 1
        if person[0] == name:
            return person[1], steps
    return None, steps
```
- วนลูปดูทีละรายชื่อตั้งแต่คนแรก นับขั้นทุกครั้งที่เปิดดู
- เจอชื่อตรง → `return` คืนเบอร์ + จำนวนขั้น **ทันที** (ลูปหยุดเลย ไม่ดูคนที่เหลือ)
- ถ้าวนครบทุกคนแล้วยังไม่เจอ → หลุดออกจากลูป → คืน `None` (ไม่เจอ)

> เปรียบเทียบ: หาเพื่อนในแถวเข้าแถวหน้าเสาธง โดยเดินดูหน้าทีละคนตั้งแต่หัวแถว

**ข้อดี:** ข้อมูลไม่ต้องเรียงก็ใช้ได้ / **ข้อเสีย:** ถ้ามี 1,000 คน แย่สุดต้องดูครบ 1,000 ครั้ง

#### แบบที่ 2: `binary_search()` — แบ่งครึ่ง

> เปรียบเทียบ: หาคำว่า "แมว" ในพจนานุกรม เราไม่ได้เปิดทีละหน้าจากหน้าแรก แต่**เปิดตรงกลาง** ถ้าเจอหมวด "ป" แปลว่า "ม" อยู่ทางหลัง → ไม่ต้องสนใจครึ่งหน้าเลย เปิดตรงกลางของครึ่งหลังต่อ ... ทุกครั้งที่เปิด หน้าที่ต้องหาจะ**หายไปครึ่งหนึ่ง** (ทำได้เพราะพจนานุกรม**เรียงตามตัวอักษร**ไว้แล้ว) และเหมือนเกมทายตัวเลขที่เราเดากลาง ๆ แล้วถามว่ามากไปหรือน้อยไป

```python
    low = 0
    high = len(contacts) - 1
    steps = 0
```
ตอนเริ่ม ช่วงที่ต้องหา = ทั้งสมุด ตั้งแต่ตำแหน่ง 0 ถึงตัวสุดท้าย (16 คน → 0 ถึง 15)

```python
    while low <= high:
```
**ใหม่! `while` = วนซ้ำ "ตราบใดที่" เงื่อนไขยังจริง**
- ต่างจาก `for` ที่รู้ล่วงหน้าว่าวนกี่รอบ ส่วน `while` จะวนไปเรื่อย ๆ จนกว่าเงื่อนไขจะเป็นเท็จ
- ในที่นี้ = "ตราบใดที่ช่วงที่ต้องหายังมีอยู่ (ขอบซ้ายยังไม่เลยขอบขวา) ก็หาต่อ"

```python
        steps = steps + 1
        mid = (low + high) // 2
        mid_name = contacts[mid][0]
```
หาตำแหน่ง**ตรงกลาง** = (ซ้าย + ขวา) ÷ 2 ใช้ `//` ปัดเศษทิ้ง เพราะตำแหน่งใน list ต้องเป็นจำนวนเต็ม (ไม่มีตำแหน่งที่ 7.5)

```python
        if mid_name == name:
            return contacts[mid][1], steps
```
ตรงกลางคือคนที่หาพอดี → เจอแล้ว คืนเบอร์

```python
        elif mid_name < name:
            low = mid + 1
```
ชื่อตรงกลาง**มาก่อน**ชื่อที่หา → ชื่อที่หาต้องอยู่**ครึ่งหลัง** → ย้ายขอบซ้ายมาไว้หลังตรงกลาง (= ตัดครึ่งหน้าทิ้ง)
ทำไม `+ 1`? เพราะตำแหน่ง mid เพิ่งดูไปแล้ว ไม่ใช่ ไม่ต้องดูซ้ำ

```python
        else:
            high = mid - 1
```
ชื่อตรงกลาง**มาทีหลัง** → ชื่อที่หาอยู่**ครึ่งหน้า** → ย้ายขอบขวามาไว้ก่อนตรงกลาง (= ตัดครึ่งหลังทิ้ง)

```python
    return None, steps
```
ถ้าตัดไปจน `low` เลย `high` แปลว่าช่วงที่ต้องหาว่างเปล่า → ไม่มีชื่อนี้แน่นอน

#### ลองทำด้วยมือ: ค้นหา "ไปรษณีย์" (อยู่ตำแหน่งที่ 15 = ตัวสุดท้าย)

| ขั้น | low | high | mid | เทียบ | ทำอะไร |
|---|---|---|---|---|---|
| 1 | 0 | 15 | 7 | ตำแหน่ง 7 มาก่อน | low = 8 |
| 2 | 8 | 15 | 11 | ตำแหน่ง 11 มาก่อน | low = 12 |
| 3 | 12 | 15 | 13 | ตำแหน่ง 13 มาก่อน | low = 14 |
| 4 | 14 | 15 | 14 | ตำแหน่ง 14 มาก่อน | low = 15 |
| 5 | 15 | 15 | 15 | **เจอ!** | คืนเบอร์ |

16 คน → ช่วงที่ต้องหาลดลงเป็น 16 → 8 → 4 → 2 → 1 ใช้แค่ **5 ขั้น** (Linear ต้องใช้ 16)

#### เทียบความเร็ว (กรณีแย่สุด)

| จำนวนรายชื่อ | Linear (ไล่ทีละคน) | Binary (แบ่งครึ่ง) |
|---|---|---|
| 16 | 16 ขั้น | 5 ขั้น |
| 1,000 | 1,000 ขั้น | 10 ขั้น |
| 1,000,000 | 1,000,000 ขั้น | 20 ขั้น |

ข้อมูลเพิ่ม **2 เท่า** → Binary ใช้เพิ่มแค่ **1 ขั้น** เพราะแบ่งครึ่งเพิ่มอีกครั้งเดียวก็เท่ากับเดิมแล้ว

## 5. ลำดับการทำงานทั้งหมด

```
เปิดโปรแกรม → เรียงรายชื่อ (sort) → แสดงรายการ → รอเหตุการณ์
   ├─ คลิกชื่อในรายการ → ใส่ชื่อลงช่องค้นหา
   ├─ "ค้นหา" → ช่องว่าง? เตือน
   │            ├─ Linear: ดูตำแหน่ง 0, 1, 2, ... ทีละตัวจนเจอหรือหมด
   │            ├─ Binary: ช่วง = ทั้งหมด
   │            │     วน while ช่วงยังไม่ว่าง:
   │            │        ดูตรงกลาง → เจอ? คืนเบอร์
   │            │                  → มาก่อน? ตัดครึ่งหน้าทิ้ง
   │            │                  → มาหลัง? ตัดครึ่งหลังทิ้ง
   │            └─ แสดงเบอร์ + จำนวนขั้นของทั้ง 2 วิธี
   └─ "เพิ่ม" → กรอกครบ? → ชื่อซ้ำ? (ใช้ Binary Search เช็ค)
               → ต่อท้าย → เรียงใหม่ → แสดงรายการ
```

## 6. คำถามที่อาจารย์อาจถาม + แนวตอบ

**ถาม: Linear Search กับ Binary Search ต่างกันยังไง?**
ตอบ: Linear ไล่ดูทีละตัวตั้งแต่ตัวแรก ถ้ามี n ตัว แย่สุดต้องดู n ครั้งครับ ส่วน Binary ดูตรงกลางแล้วตัดทิ้งทีละครึ่ง ข้อมูล 1,000 ตัวใช้แค่ประมาณ 10 ครั้ง แต่ Binary ใช้ได้เฉพาะข้อมูลที่เรียงแล้วครับ

**ถาม: ทำไม Binary Search ต้องเรียงข้อมูลก่อน?**
ตอบ: เพราะตอนดูตรงกลาง เราตัดสินว่าชื่อที่หาอยู่ครึ่งหน้าหรือครึ่งหลัง ถ้าข้อมูลไม่เรียง ชื่อที่หาอาจอยู่ในครึ่งที่เราตัดทิ้งไปแล้วครับ เหมือนพจนานุกรมที่หน้าสลับกันมั่ว จะเปิดตรงกลางแล้วเดาฝั่งไม่ได้

**ถาม: งั้น Binary ดีกว่า Linear เสมอไหม?**
ตอบ: ไม่เสมอครับ ถ้าชื่อที่หาอยู่บนสุดพอดี Linear ใช้ 1 ขั้นแต่ Binary ใช้ 4 ขั้น และถ้าข้อมูลน้อยมาก ๆ หรือยังไม่ได้เรียง Linear ง่ายกว่า แต่ถ้าข้อมูลเยอะและค้นหาบ่อย Binary คุ้มกว่ามาก

**ถาม: ข้อมูล 1 ล้านตัว Binary ใช้กี่ขั้น?**
ตอบ: ประมาณ 20 ขั้นครับ เพราะ 2 ยกกำลัง 20 ประมาณ 1 ล้าน แบ่งครึ่ง 20 ครั้งก็เหลือตัวเดียว (ในวิชา CS เขียนว่า **O(log n)** อ่านว่า "โอ-ล็อก-เอ็น" ส่วน Linear เป็น **O(n)**)

**ถาม: ทำไมใช้ while แทน for?**
ตอบ: เพราะไม่รู้ล่วงหน้าว่าต้องแบ่งครึ่งกี่ครั้ง ขึ้นกับว่าเจอเร็วแค่ไหน while วนไปเรื่อย ๆ ตราบใดที่ช่วงที่ต้องหายังไม่ว่างครับ

**ถาม: ทำไมโรงเรียนกับไปรษณีย์ไปอยู่ท้ายสุด?**
ตอบ: Python เรียงข้อความตามรหัส Unicode ซึ่งสระหน้า เ แ โ ใ ไ มีรหัสมากกว่าพยัญชนะ เลยไม่เหมือนพจนานุกรมไทยครับ แต่ Binary Search ยังทำงานถูก เพราะการเรียงกับการเทียบใช้กฎเดียวกัน

**ถาม: ทำไมเพิ่มรายชื่อแล้วต้อง sort ใหม่?**
ตอบ: เพราะต่อท้ายแล้วลำดับจะไม่เรียง Binary Search จะตัดครึ่งผิดฝั่งแล้วหาไม่เจอครับ
